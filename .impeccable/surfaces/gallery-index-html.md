# Public playground

Mode: Experience. Target: gallery/index.html. Related targets: gallery/playground.ts, gallery/playground.css, gallery/catalog.ts, gallery/garden-state.ts.

The user confirmed a curated plant chooser and a code-led build using real gardens. The existing botanical artwork and historical palettes remain the visual authority. The specimen gallery remains available separately. The public interface adds no library growth features.

## Direction contract

THESIS: The preview shows a generated garden beside readable text. Visitors adjust the artwork in place rather than navigate a generator parameter panel.

OWN-WORLD: Baskervville supplies the botanical plate's lettering. A subdued green interface surrounds the selected palette's paper, ink, wash, and accent. Rules separate functional groups. Generated SVG plants supply the illustration.

STORY: Visitors choose a familiar plant visually, change its inks, adjust its place beside text, and export the current garden. Historical names remain secondary.

FIRST VIEWPORT: A compact masthead sits above a broad page preview and a narrow control column. The preview contains a readable text sample beside a full-height garden. The plant chooser leads the controls, followed by colour previews. On a phone the artwork stays above the controls at a useful scale.

FORM: The user-approved interactive botanical plate extends the existing artwork's visual system. Seed: none (direction pinned in the conversation).

SIGNATURE: Palette and time changes update the same composed plant. Margin changes move the text boundary without stretching the SVG. Selecting another seed changes only the composition.

## Scope

The playground includes:

- Curated plant thumbnails with English names.
- Eight named palette swatches.
- Engraving and wash with light and dark readings.
- Left and right placement with adjustable margin room.
- Optional time and fullness controls.
- A date-based calendar.
- Share, SVG export, and code actions.

Controls support touch and keyboard. Standalone SVG exports embed guest figures and retain required attribution. The static build supports subdirectory hosting. GitHub Pages publication requires repository Pages configuration and a push or manual workflow run. This task does not publish remotely.
